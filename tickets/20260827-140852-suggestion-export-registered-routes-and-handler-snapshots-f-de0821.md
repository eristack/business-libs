## Summary

Tiga Sekawan Horizon B is peek Backseat handlers then write Express. No first-class listRoutes/snapshot API; agents grep apps/web/src/backseat/routes. A route table would make derivation mechanical.

## User story

As an agent deriving Express from Backseat I want a route inventory instead of grepping registerRoute calls.

## Proposed behavior

api.listRoutes() returns method, path, name, and a serializable contract (request/response examples optional). Devtools already peek; agents need a file or JSON dump for Horizon B Express.

## Proposed API

listRoutes(): RegisteredRouteMeta[]; maybe writeRoutesSnapshot(path)

## Feasibility rationale

Likely doable as an additive / adapter-scoped change.

## Implementation sketch

- Collect registerRoute metadata already on the engine
- Optional BackseatDevtools export button + JSON
- Docs: peek handlers when building Express — Tiga Sekawan IMPLEMENTATION Horizon B

## Risks

- Handler functions are not serializable. Export metadata only (method, path, name), not closures.
- Snapshot files must not include secrets from seed.

## Alternatives

- Agents grep `registerRoute` (current Horizon B plan in IMPLEMENTATION §12.3).
- OpenAPI generated by the app, not the engine.
