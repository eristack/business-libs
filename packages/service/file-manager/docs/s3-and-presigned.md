# S3 and presigned URLs

## Driver

```ts
import { createS3StorageDriver } from "@eristack/file-manager/s3";

const driver = createS3StorageDriver({
  bucket: "my-app-uploads",
  region: "ap-southeast-1",
  // MinIO / LocalStack / R2:
  endpoint: "http://127.0.0.1:9000",
  forcePathStyle: true,
});
```

IAM: allow `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject`, `s3:HeadObject` on `bucket/*` (scoped by your `keyPrefix` convention).

## Object keys

Keys are generated by `buildObjectKey`:

```text
{keyPrefix}/{namespace}/{yyyy}/{mm}/{fileId}{ext}
```

Set `keyPrefix` on `createFileManager` (e.g. `prod/tenant-123`).

## Presigned browser upload

1. `POST /files/uploads/presign` — body: `originalName`, `mimeType`, `sizeBytes`, optional `namespace`
2. Client **PUT** to `uploadUrl` with required headers (typically `content-type`)
3. `POST /files/uploads/complete` — body: `fileId`

Default TTL: **15 minutes** (override via `presign.putExpiresInSeconds` / `getExpiresInSeconds` on `createFileManager`).

## Downloads

`GET /files/:id/download-url` returns `{ url, expiresAt }` — redirect or open in a new tab.

Optional `downloadFilename` is passed to S3 `ResponseContentDisposition` when using the core API directly.
